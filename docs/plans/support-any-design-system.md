# Plan: Support any design system by publishing the auk role layer as a contract

## Objective

Publish the semantic role layer the ui-theme skill already carries as a machine-readable contract, a generated DTCG token file plus a generated roles stylesheet, so a design-system team binds at most 23 roles once and every auk component follows. Then extend that one layer through the theme skill's discovery and output, the generated anatomy names Figma shares, the spec rows and guides that state the rule, the evals that prove a request reaches it, and a generated component sheet that shows the whole set painted by the shipped CSS.

## Context

Every component under `skills/` writes each visual value as `var(--auk-<component>-<property>, <literal>)`, and the literal is why a component works with nothing bound. A parser run over the six references on 2026-09-04 counts 137 unique properties: 69 brand-bearing (57 colours, 7 corner radii, 5 font families) and 68 measured (spacing, sizes, type, placement, one duration); `tests/unit/ui-theme-mapping.spec.ts` pins that split. The ui-theme workflow skill maps 21 roles onto the 69 brand properties, but only as a prose table in `skills/ui-theme/references/ui-theme.md` that an agent reads and a human follows by hand. A team with an established design system therefore binds up to 69 lines to get one brand in, and nothing in the tree can be read by a token build or imported into a design tool.

The proposal at `docs/prompts/proposal-support-any-design-system.md` (published at https://claude.ai/code/artifact/fe77138e-4ea8-4b51-a6de-a31057fa5653) surveyed twelve design systems and the W3C Design Tokens Community Group (DTCG) format 2025.10, the first stable version of the token file standard. Every system binds at the semantic tier, the tier that names a colour by its job rather than its value, and the ones that once exposed component tokens as the front door are retiring them. So the contract is the role layer, published in two generated forms: `auk.tokens.json`, a DTCG file in which each role is a token and each component property is a token aliased to its role, and `auk-roles.css`, a stylesheet inside `@layer auk` that chains every brand-bearing component property to a `--auk-role-<name>` property. A component reference never reads a role, so the standalone guarantee the gates enforce is untouched, and an unbound role makes the chained property invalid at computed-value time so the shipped literal applies, which `tests/e2e/ui-theme.spec.ts` already proves for one hop. Seventeen decisions in that proposal are settled inputs here, not open ones.

This plan starts where plan #27 ends. `docs/plans/enable-simple-component-style-overrides.md` (status completed, merged to main on 2026-09-04 as https://github.com/shawn-sandy/agent-ui-skills/pull/33 for issue #27) wraps every reference css block in `@layer auk`, adds the shared parser `scripts/auk-properties.mjs`, the catalog generator `scripts/build-properties.mjs` with `docs/properties.md`, and the consumer guide `docs/theming.md`. The token generator imports that parser, the anatomy section extends that catalog generator, the integration checklist extends that guide, and the roles file joins that layer. Step 1 checks for all four and stops if any is missing.

Planning found one defect in the role table the proposal carried over unchanged. Two roles chain a control's text colour to its own background: `muted` covers `--auk-button-disabled-bg`, `--auk-button-disabled-border-color` and `--auk-button-disabled-color`, and `inverse` covers `--auk-box-invert-bg`, `--auk-box-invert-color` and `--auk-box-invert-border-color`. The existing browser test never hit it because its 69-line palette sets each property separately (disabled background `#57534e`, disabled text `#ffffff`). A roles file cannot: the moment a project binds `--auk-role-muted`, the disabled button's text and background become the same colour. The table gains `on-muted` and `on-inverse`, mirroring the existing `primary` and `on-primary` split, which makes 23 roles. Every count below reads 23 for that reason.

The prototype at docs/prototypes/bind-design-system-roles.html measured a second trap on 2026-09-04. A custom property resolves where it is declared: the roles file chains `--auk-button-bg` to `--auk-role-primary` on `:root`, so a role set lower in the tree, on a `[data-brand="acme"]` wrapper or a `<body class="dark">`, is never seen by that chain and the button keeps the root brand. The proposal's one-line scoped block therefore does nothing on its own. The rule this plan adopts: any block below the root restates the chain lines for the roles it sets, copied from that role's group in the roles file, and ui-theme emits them automatically; the browser suite proves both that the restated block works and that the bare one does not. Anchoring the roles file on a universal selector was rejected because a layered declaration on every element would beat an unlayered `:root` override of a component property, closing the escape hatch plan #27 promises.

A DTCG file cannot type every shipped fallback. The parser run lists twelve literals with no token type: `inherit` on the five font-family properties, `auto` on `--auk-box-min-block-size`, `min()` on the dialog and popover inline sizes, `calc()` on their maximum block sizes, and the two popover placement values. Nine `transparent` fallbacks are colours with alpha zero and encode cleanly. The generator keeps the category type on the twelve, carries the literal verbatim as a string value with a `raw` flag, and the unit test names each one, so nothing is invented and a strict validator's complaint points at a known list.

Measured floors come only from tests. The suite asserts today that the button clears 44 by 44 CSS pixels (`tests/e2e/ui-button.spec.ts`, WCAG 2.5.8 Target Size); the maintainer chose on 2026-09-04 to record the WCAG bound of 24 by 24 as the floor and to lower that assertion to match, so the shipped 2.75rem still clears it but is no longer pinned at 44. The suite also asserts that a focus outline is wider than zero on five components (2.4.7 Focus Visible), that the focus ring clears 3:1 against its surface (`tests/e2e/ui-theme.spec.ts`, 1.4.11 Non-text Contrast), and the button reference keeps its transition inside a reduced-motion guard. The tab, dialog-close and popover-close target sizes are not asserted, so their tokens carry `floor: none` rather than a number nobody measured. Dimension roles with floors (the proposal's Workstream C) are left for a follow-up plan by the maintainer's choice on 2026-09-04, so the token file records floors and the theme skill still binds brand only.

Vendor neutrality is the project's stated purpose, so every surface that depends on one vendor is labelled where it appears and paired with the neutral path that is the record: the token file imports into Figma and Penpot, but the file itself is the contract; the agent-driven Figma collection and the Code Connect example are optional and plan-gated; the Claude Design canvas and the internal `design-kit` skill are projections of the generated HTML component sheet; and `figma-generate-design` is named only as an on-request bridge from that sheet. The portability lint bans framework, preprocessor and package names under `skills/` only, which is why token build tools and Code Connect are named in `docs/` and never in the theme reference.

Known risks and their mitigations. A misspelled role name makes the chain fall back to the literal and looks like "the theme did nothing": the browser suite gains an unbound-role case, and the reference's Verification section tells the agent to read computed styles rather than the eye. Figma's own guidance says a semantic variable should alias a primitive, not another semantic: the reference states the trade (23 bindings instead of 137) and names binding component properties directly as the alternative. Token tools lag the 2025.10 specification, so step 10 runs a real Style Dictionary build over the file and records what happened instead of trusting the proposal's sentence. The qualifier line declares parts that are not `data-part` attributes (the dialog declares `title`, `close` and `backdrop`; the tabs declare `tab` and `panel`, which the markup addresses by ARIA role), so the anatomy renderer marks whether each part is an attribute rather than assuming. `skills/ui-theme/SKILL.md` has 53 body lines against a cap of 100, raised from 60 by pull request #35 on 2026-09-04, so the additions below fit without rewriting the body. The eval sweep has no per-skill filter and costs about 75 model calls; it runs once, in step 24. Acceptance requires the four new scenarios to pass on all three models (maintainer, 2026-09-04); docs/evaluations.md records Haiku invoking no skill at all on ten of twelve scenarios across two description rewrites, so that criterion may not be reachable by any wording, and if it is not the plan stays in-progress and reports the miss instead of closing.

## Decisions

- One phase per workstream in the proposal's roadmap order (A, B, D, E with F, G), each opening with the test that must fail. Chosen by the maintainer on 2026-09-04 over RED, GREEN and VERIFY headings across the whole plan, which would have put about twenty steps in one GREEN run, and over six separate plans.
- Workstream C, dimension roles with floors, is out of this plan. The maintainer left open question 1's dimension half open on 2026-09-04; its prompt sits under Next Steps and the floors the token file records are only the ones the suite asserts today.
- `auk.tokens.json` and `auk-roles.css` live in `skills/ui-theme/references/` (maintainer, 2026-09-04). Installers copy skill directories, so an installed ui-theme carries both; both therefore pass the portability lint and the external-resource guard, and neither names a token build tool.
- Plan #27 is a prerequisite, not absorbed. Its parser, catalog generator, guide and layer are imported or extended here; duplicating them would fork four files that plan owns. It merged to main on 2026-09-04 as pull request #33, so step 1's check passes today and stays as a guard for a branch cut before that merge.
- The mapping table grows from 21 to 23 roles with `on-muted` and `on-inverse`, because a role that binds a control's text and background to one value blanks the text the moment a project binds it. The 69-property total, the 57/7/5 split and the 68 measured properties are unchanged.
- A role token's `$value` is the shipped fallback of the first property in its mapping-table row, and every component token carries its own shipped literal verbatim under `$extensions`, so aliasing a component token to its role loses nothing a reader could want back.
- The twelve untypeable fallbacks keep the category `$type`, carry the literal as a string `$value` and a `raw: true` flag under `$extensions`; `transparent` encodes as sRGB black at alpha zero. A strict validator may flag the twelve; the unit test lists them so the count cannot drift silently.
- The `$extensions` key is `com.github.shawn-sandy.agent-ui-skills`, the reverse-domain form the DTCG format module recommends, derived from the repository URL.
- A floor is the bound the suite asserts, named with the spec file that asserts it. The button's floor is the WCAG 2.5.8 minimum of 24 pixels, and the assertion in tests/e2e/ui-button.spec.ts is lowered from 44 to 24 in this plan so the token file records what the test proves (maintainer, 2026-09-04). Adding the unasserted tab, dialog-close and popover-close targets is Workstream C's call.
- The Code Connect example is a fenced block inside `docs/theming.md`, not a file. The package is not installed, so a file could never be type-checked, and a labelled example is honest where an unverifiable module is not.
- `tests/e2e/ui-theme.spec.ts` rewrites its palette to the version-two shape, the roles file plus 23 role lines, rather than duplicating every measurement. The file's stated job is to measure what ui-theme emits, and the 69-property guard survives through the roles file, which sets all 69.
- `scripts/build-design.mjs` carries its own five-line fenced-block helper. `scripts/build-demos.mjs` runs its main body on import, as `scripts/skill-kind.mjs` documents, so nothing can import from it.
- The generated HTML component sheet is the design-side record. `--canvas` and the `design-kit` skill are the labelled Claude Design projection; a Figma kit is built from the sheet with `figma-generate-design` only when a team asks.
- The `prefers-contrast: more` block is prose only, like the dark block. No demo declares a contrast form, so an emulated-media browser case would measure the emulation rather than the skill (maintainer, 2026-09-04).
- The version bumps from 0.3.0 to 0.4.0 in this plan, because the ui-theme skill's emitted block changes shape and a consumer pinning 0.3.0 should get a signal (maintainer, 2026-09-04).
- The four new eval scenarios must pass on all three models before the plan closes (maintainer, 2026-09-04), knowing docs/evaluations.md records Haiku as unreliable at invoking any skill; a miss leaves the plan in-progress with the miss reported.
- Blocks below `:root` restate the chain. The roles file anchors the chain on `:root` only; a dark, brand or density block on any lower element carries, for each role it sets, that role's chain lines from the roles file. Measured in the prototype on 2026-09-04: without them a scoped role never reaches the component. A universal selector was rejected because it would beat the unlayered `:root` property override that is door one of docs/theming.md.
- Type is `feature`. The leading verb "Support" is outside the inference table, and the work ships two generators, six test files and skill changes, so `chore` would misdescribe it.
- No SHIP phase and `workflow: never`. The request was to plan the work, the phases are sequential, and each closes on a green `npm run check` so a fresh session can pick up at any boundary.
